# Результаты замера Debug vs Release
| режим | Запуск 1 | Запуск 2 | Запуск 3 | Запуск 4 | Запуск 5 | Минимум |
| Debug |  360мс   |  395мс   |  366мс   |  750мс   |  370мс   |  360мс  |
|Release|  354мс   |  116мс   |  117мс   |  122мс   |  112мс   |  112мс  |
В моём эксперементе Release оказался быстрее Debug примерно в 3.2 раза.
Что я обнаружила при сравнении IL:
1. в Debug присутствует инструкцуия nop, которых нет в Release;
2. в Release уменьшилось количество промежуточных операций с локальными переменными;
3. Количество IL-инструкций в методе Add() изменилось с 11 до 4

# Ответы на контрольные вопросы:
1. IL-это промежуточный язык. Компилятор переводит C# в IL, а при запуске JIT превращает его в машинный код (понятный процессору). Нужен,чтобы одна программа работала на разных системах без перекомпиляции.
2. Внутри .dll лежит IL-код и метаданные (названия классов, методов). Специальные программы (ILSpy) читают их и восстанавливают исходный код. Полностью спрятать код нельзя
3. В Debug куча лишнего: команды nop (для отладки), отдельные операции для каждой переменной. В Release это всё выкидывается. Метод Add в Debug - 11 инструкций, в Release - 4
4. Debug не оптимизируется, а Release оптимизируется под скорость. В моём замере Release быстрее в 3.2 раза: 360 мс против 112 мс
5. Строки в .dll хранятся как обычный текст. Их видно в Hex-редакторе (HxD) или через декомпилятор. Пароли и ключи в коде хранить нельзя
